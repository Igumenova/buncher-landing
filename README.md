# Buncher

Чистая основа для нового лендинга: HTML, JavaScript, SCSS и Webpack.
Рабочая ветка — `redesign`. На странице пока только заголовок Buncher.

## Запуск

Нужны Node.js 20+ и npm. Все команды выполняются из папки `buncher`.

```sh
npm ci
npm start
```

Локальный адрес: `http://localhost:4200`. Изменения обновляются автоматически.
Если зависимости уже установлены, достаточно `npm start`.

```sh
npm run build  # production-сборка в dist/
npm run dev    # разовая development-сборка с картами исходников
```

## Исходники

- `src/index.html` — разметка страницы.
- `src/index.js` — точка входа JavaScript и подключение стилей.
- `src/styles/style.scss` — основные стили.
- `src/styles/_tokens.scss` — базовые цвета, шрифт и отступы.
- `src/styles/_reset.scss` — минимальный сброс стилей браузера.
- `src/scripts/` — будущие скрипты нового сайта.
- `src/img/` — логотипы и фавиконки; содержимое копируется в `dist/img/`.

Импорты через `@/` отсчитываются от `src/`. Настроены Babel, Autoprefixer,
обработка изображений и шрифтов, минификация production-сборки.
Зависимости и их lock-файл сохранены без обновления версий.

## Старый дизайн

Старый сайт целиком сохранён **в этом же Git-репозитории**:

- ветка `legacy` — исходники и конфигурация старого сайта;
- тег `design-v1` — фиксированный снимок перед редизайном;
- папка `../buncher-legacy/` — локальная рабочая копия ветки `legacy` через Git worktree.

Архив доступен через выбор ветки `legacy` в репозитории. В текущем дереве
нового сайта отдельной папки с архивными исходниками нет.
Worktree использует Git из `buncher/.git`; это не независимая резервная копия.

После клонирования репозитория архивную папку можно восстановить:

```sh
git worktree add ../buncher-legacy legacy
```

Если доступна только удалённая ветка `origin/legacy`:

```sh
git worktree add -b legacy ../buncher-legacy origin/legacy
```

## Публикация

GitHub Pages настроен на push в `main`. Работа в `redesign` сама по себе
не публикует новый сайт. Workflow также поддерживает ручной запуск.
